## feat/agents-architecture

Written 2026-10-17, design only (no code): `docs/AGENTS_ARCHITECTURE.md` and
`docs/PROMPT_GUIDE.md`, for the flow agreed with the owner that day. Owner
rule: the owner writes every prompt and every `agents.toml` value; code never
supplies a default prompt, model or Meta rule. The choices below are open to
the owner's review before job 2 starts.

| # | Decision | Conservative because | Alternative |
|---|---|---|---|
| AA1 | `docs/AGENTS_ARCHITECTURE.md` didn't exist on any branch, so it is a new file. It builds on `agents/DESIGN.md`, `docs/AGENTS_TECHNICAL_DESIGN.md` and the PR #16 draft and edits none of them. | No rewrite of documents that record past decisions. | Fold the flow into `agents/DESIGN.md`. |
| AA2 | Decision arms: `blind` keeps its name for the decision after round 1; `discussion` and `technical_v1` are added; `debate` stays allowed for old rows only. | Existing rows and queries keep their meaning; append-only history isn't renamed. | Rename `blind` to `round1`. |
| AA3 | The model can't abstain. Abstain means the infrastructure got no valid answer (error, refusal, truncation, invalid output, budget) and is stored apart from `none`, which is the model's choice. | Keeps "no position" and "no answer" separate, as the skeleton already does. | Let the model return `abstain`. |
| AA4 | A `long` or `short` vote needs at least one evidence ref that resolves; without one, the agent abstains. | A direction is never taken on unchecked grounds. | Accept directional votes without evidence. |
| AA5 | Vote-change rule: a change of direction or confidence in the discussion needs a snapshot ref that wasn't in the agent's previous vote. A `vote:` ref (citing another agent) never counts on its own. | Stops agents converging on each other's say-so (herding) instead of on evidence. | Any ref, or `vote:` refs allowed alone. |
| AA6 | A rejected change, or a failed or invalid discussion call, carries the agent's previous vote forward with `change_rejected` set. It's not an abstain. | One failed round can't erase a valid round-1 vote, and the discussion arm never has fewer valid votes than the blind arm because of infrastructure. | Abstain on any discussion failure. |
| AA7 | The discussion speakers are the LLM agents whose round-1 vote didn't abstain. Rounds are simultaneous (round r sees the others' round r − 1). Views are content only (no model ids, timings, tokens). GEX and abstained agents are shown as they are. | Mirrors the existing debate's simultaneous rounds and `content_only`; no agent gains from speaking last. | Sequential turns; abstained agents retry in the discussion. |
| AA8 | A discussion request is stateless: system + the agent's round-1 user content (byte-identical) + the rendered `discussion.md`. No assistant turns are replayed. | A pure function of (snapshot, votes); no dependence on thinking-block replay rules; the shared prefix is cacheable within the run. | Multi-turn conversations per agent. |
| AA9 | The same Meta rule and parameters decide both `blind` and `discussion`. A missing or unknown rule → Meta abstains (decisions `none`, with the reason). `technical_v1` never enters Meta. | The two arms differ only by the discussion; there's no default rule; the benchmark stays independent. | Separate rules per arm. |
| AA10 | `epoch_id` is a hash over prompt bytes, the validated config, models, schema, input-building code, the Meta rule, the σ model and the journal epoch. A changed prompt with an unchanged front-matter `version` logs a warning; the epoch changes anyway. | No change can slip into an epoch unnoticed, and nobody has to remember to bump anything. | Epoch = the owner's `version` strings. |
| AA11 | Refusal fallbacks (the API's `fallbacks` parameter) stay **off**. The Claude API reference recommends opting in by default for Opus 5.5 / Sonnet 5.5, but a fallback answers with another model, which breaks the frozen-model rule inside an epoch. A refusal is an abstain with its category. Same rule as the agents v1 design §4 and PR #16. | One model per epoch, always. | Opt in to fallbacks and record the serving model. |
| AA12 | Prompt file format: front-matter `agent` (= file name) and `version` required, `description` optional, other keys invalid; `## system` then `## user`; no placeholders in `## system`; `discussion.md` has `## user` only. Unknown placeholders, or discussion placeholders in a round-1 file, make the file invalid (abstain). | Strict parsing surfaces mistakes as visible abstains instead of silently different prompts, and keeps round 1 blind by construction. | Free-form files with lenient parsing. |
| AA13 | The cost estimate assumes 2k-token system prompts, three 1000 × 600 charts (≈ 800 tokens each), `effort = medium` on every LLM agent, 2 discussion rounds with half the runs stopping early, and 5 alerts a day, at the list prices of the Claude API reference (cached 2026-10-06). | Ranges, not points; the real cost is logged per call. | Measure with `count_tokens` first (planned before any freeze). |
| AA14 | Technical v1 runs in the same run, on the same snapshot, as its own arm. It's invisible to the other agents and isn't counted by Meta; its decision is its vote. | A benchmark on exactly the same alerts that can't influence what it benchmarks. | A separate runner. |
