# docs/tidy

PR 3 of [the restructure plan](../history/RESTRUCTURE_PLAN.md) (§7): current
docs in `docs/`, the rest in `docs/history/`, the root decision log split per
branch, `ARCHITECTURE_CURRENT` redrawn, and a link checker. No code or
behaviour changes. Decisions taken without the owner, each with its
alternative.

| # | Decision | Conservative because | Alternative |
|---|---|---|---|
| DT1 | **`docs/DECISIONS.md` is split into 13 files, `docs/decisions/<branch>.md`**, one per `## <branch>` section, named as BL12 (`/` → `-`). Each file is its section with the heading raised to `#`, otherwise byte-identical; a script checked every section against the original. The file's two-line intro moves into the new index, `docs/decisions/README.md`, which lists every branch file with its PR. | Content unchanged, as asked; one naming rule for old and new files. | One file per PR number, or keeping the old file as a stub that points to the folder. |
| DT2 | **Five docs move to `docs/history/`** with `git mv`: `ARCHITECTURE_MAP`, `REPO_MAP`, `CLEANUP_NOTES`, `DEPLOY_PLAN` and `RESTRUCTURE_PLAN`, the list in the plan. Each gets one `> **History.**` line under its title (what it was, what superseded it). Otherwise they stay as written; the only other edit is the one relative link that would have broken (`RESTRUCTURE_PLAN` → `../decisions/`). | Records stay records; git shows each as a rename with 2–4 changed lines. | Update the paths inside them. |
| DT3 | **References to the moved files:** path mentions in current docs, READMEs and a test comment now name `docs/history/…` or the split decision file (`docs/decisions/feat-deploy-stack.md` D3 and D14, `feat-agents-architecture.md`, `research-level-target-spec.md`). In decision records only the link targets change (`refactor-backend-layout.md`, `refactor-scanner-package.md`), not their text. The runbook's §13 table keeps `docs/DECISIONS.md` as #34's new path and says it was split since. | Records keep their wording; nothing points at a missing file. | Rewrite the records' text too (as RT6 did for #34). |
| DT4 | **`SCANNER_SWITCH_NOTES` stays in `docs/`.** The runbook doesn't cover everything still operational in it: it cites the notes' §4 for why an image from before the journal migration can't write a migrated journal (and the notes alone have the `DROP COLUMN` recipe for that case), and §5c for the open IBKR "10 D" question that `tools/ibkr_duration_check.py` answers. The notes get one header line saying their paths are from before the restructure. | The plan's condition ("moves only after the runbook covers everything still operational") isn't met, so it doesn't move. | Copy §4's recipe and §5c into the runbook and move the notes (a runbook change, better in its own PR). |
| DT5 | **`PROMPT_GUIDE`, `LANGGRAPH_STUDIO`, `DATAFEED_NOTES`, `AGENTS_ARCHITECTURE`, `AGENTS_TECHNICAL_DESIGN` and `AGENT_LLM_SCANNER_DESIGN` stay**, with their package paths and commands updated to the new layout by a script: `agents/…` → `backend/agents/…` (also `datafeed`, `scoring`, `risk`), `python -m agents.…` → `python -m backend.agents.…`, `tests/agents_tests/` → `tests/agents/`. Every renamed path exists, apart from the planned, unbuilt files in `AGENTS_TECHNICAL_DESIGN`'s table (still plans). One reference named a file that no longer exists: `agents/debate/evidence.py` is now `backend/agents/evidence.py`. The five `python -m` commands were run (`--help`). `DATAFEED_NOTES`' build-time records of `backend/deterministic_scanner.py` (baseline, hashes) stay as written. | These docs are current and their commands must work; records inside them don't change. | Move `DATAFEED_NOTES` to history: it is a branch's working notes, but it is still the reference for the bar contract and its deviations. |
| DT6 | **The root is unchanged here.** #34 (`chore/repo-root-tidy`, merged while this PR was queued) already left only `.github/`, `.gitignore`, `README.md`, `pyproject.toml` and folders, with the owner's layout: the locks and the cutoff in `requirements/`, `langgraph.json` in `tools/langgraph_studio/`, `.env.example` in `deploy/`. That covers the root-file moves added to this PR, with one difference: `requirements.lock` is in `requirements/`, not at the root. | The owner's merged layout wins; no second move. | Move `requirements.lock` back to the root. |
| DT7 | **Link checker: `tools/check_links.py`**, stdlib only. It checks every relative Markdown link (`[x](path)` and reference definitions) in tracked and new `.md` files; it skips external links, anchors, fenced and inline code, and `legacy/` (frozen). It runs as a CI lint step. It doesn't check `#anchors`, or paths written in backticks. Result: 0 broken links. | No new dependency; it catches the failure this PR could cause. | `lychee` or `markdown-link-check` (a new tool to pin and verify), or anchor checking. |
| DT8 | **`ARCHITECTURE_CURRENT` is redrawn from `main`:** a new §0 (the repo tree and an import graph of the `backend` packages, checked against the imports); every diagram's paths and commands in the new layout; §(d) replaced by three agents diagrams (the run graph with what is built, stub or LLM-only; the discussion; one LLM call); the EC2 state as the owner gave it (c62810d). The Mermaid blocks render with `@mermaid-js/mermaid-cli` 11.4.2 (12 of 12). | Drawn from the code, not the design docs; same legend and conventions as before. | Leave the agents section and add a pointer to `AGENTS_ARCHITECTURE`. |
