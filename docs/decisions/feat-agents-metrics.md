# feat/agents-metrics (agents v2, job 5)

Built 2026-10-17, stacked on `feat/agents-discussion` (#23).

| # | Decision | Conservative because | Alternative |
|---|---|---|---|
| M1 | **The snapshot builder computes the features** (HAR σ at 60/240, `sigma_ret_*`, `crosses_close_*` as 0/1, L, S_hd, T) from its own fetched bars, with `datafeed.features.vol_block`. The agents package boundary test now allows that one module. | One query, one `known_by`, the same as the bars (design §2); σ-relative metrics need it. | Features in a separate node with its own query. |
| M2 | **The σ model is named in the infra config** (`snapshot.sigma_model`; the example sets `parquet2021_2023`, the PREREG's pin). There is **no code default**: without a model, features are unavailable with the reason. Its SHA-256 enters the epoch, and the name and SHA are on every snapshot. | No silent model choice; a different model is a new epoch. | Default to vol_block's DEFAULT_SIGMA_MODEL. |
| M3 | **Feature failures never raise:** no model, an unknown name, a bad file or SHA, too little history (`insufficient_history`: the vol state needs about 5 trading days) or a missing pandas all become the reason. The model's provenance is kept when the state is invalid. | A broken input shows as unavailable, never crashes the run. | Raise. |
| M4 | **The metric table is always built** and never imputed. Each row that can't be computed carries its reason; volume and VWAP are always unavailable ("no volume source …"). The `metrics` slot is no longer marked unavailable. | A prompt always sees the full table, with reasons, not a missing slot. | Leave the slot unavailable until every row exists. |
| M5 | **Wilder ATR and RSI seeded with the simple mean** of the first n values, and EMA seeded the same way. RSI with no losses is 100; a flat series is unavailable. RSI is checked against the StockCharts worked example: its table rounds the averages, so the exact values are ≈ 0.07 lower, and the test pins the exact ones within 0.1 of the published ones. | The textbook definitions, with an external reference. | pandas `ewm` variants (different seeds). |
| M6 | **`L_tercile` isn't built.** Its cut-offs ("fixed from the σ model's training window") aren't defined anywhere yet. The guide says not to reference it. | No made-up cut-offs. | Terciles of the snapshot's own L history. |
| M7 | **`dist_sigma_<level>` rows** appear once the level library fills `snapshot.levels`. Today the levels slot is empty (unavailable), so there are none. | The rows follow the data; no placeholder rows. | One unavailable `dist_sigma` row. |
| M8 | **Measured:** a snapshot with features takes ~373 ms against ~335 ms without, on the development Mac (30-day fetch; 5 runs after a warm-up). It runs once per alert, so nothing continuous is added. | Measured before deciding nothing needs optimising. | Cache the vol state. |
| M9 | **The Technical v1 agent isn't built here.** It is agents v1's Technical agent (its own PREREG). The table it will read, and `metric(rows, name)`, are in place. | Job 5 is the shared table, as asked. | Build the deterministic agent too. |
