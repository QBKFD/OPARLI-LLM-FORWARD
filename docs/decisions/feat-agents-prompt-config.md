# feat/agents-prompt-config (agents v2, job 2)

Built 2026-10-17 on top of `feat/agents-architecture` (#17), whose design it
implements. Owner rule: the owner writes every prompt and every
`agents.toml` value; code never supplies a default.

| # | Decision | Conservative because | Alternative |
|---|---|---|---|
| P1 | **The branch is stacked on #17**, not cut from `main`: it implements that design and updates its two docs. The PR says to merge #17 first. | The code and its contract stay in step; nothing in `main` is assumed. | Cut from `main` and copy the docs. |
| P2 | **Two config files.** The owner's `agents.toml` (`$AGENTS_CONFIG`, `agents/owner_config.py`) holds only owner values. The infrastructure config (`agents/config.py`: snapshot, gate, timeouts) is unchanged. | The owner's file never mixes with infrastructure; Studio (#15) and the existing tests keep their config. | One file with both. |
| P3 | **Owner config problems never raise.** Each accessor returns the settings or a `ConfigProblem`, and the caller abstains with `config_invalid: <key>: <problem>`. An unreadable file makes every section a problem. Strict types: no `"16000"` → 16000 coercion. Unknown keys inside a block make that block invalid (a typo can't be ignored). | One bad value can't stop the run or silently take a default. | Fail the whole build on any config error. |
| P4 | **No code defaults** for model, effort, `max_tokens`, Meta rule, LLM mode, timeout, retries, budget or bar rows. The only defaults are the owner's: `discussion.rounds = 2`, `early_stop = true`. A value still reading `"<...>"` (copied from the example) is refused. | It is the owner's rule; the example can't work unfilled. | Infrastructure defaults for timeouts and retries. |
| P5 | **Model ids:** an exact `claude-…` id. An alias (`-latest`) or a date suffix is refused. The id isn't checked against a list, so new models need no code change; job 3 checks the served model against the requested one. | Pins what the owner wrote, without code deciding which models are allowed. | An allowlist of models. |
| P6 | **The templates are refused** until the owner writes them: front-matter `version: TEMPLATE` is an "unfilled template". Their instructions-free comments list the placeholders. | No template can ever reach a model as a "default prompt". | Templates that load as empty prompts. |
| P7 | **`<!-- ... -->` comments are stripped** from sections (and allowed before the first section). The file hash covers the raw bytes, comments included. | The owner can keep notes in a prompt without sending them; any edit is still a new epoch. | No comments; or comments not in the hash. |
| P8 | **Round-1 placeholders aren't allowed in `discussion.md`**, and discussion placeholders aren't allowed in round-1 files. | Round 1 stays blind by construction, and the discussion turn has one clear input set (its round-1 content is resent before it). | Allow round-1 placeholders in the discussion. |
| P9 | **Snapshot schema 3.** It adds the alert facts (allowlisted from the trigger payload's `alert`), `trigger_levels`, `metrics`, `charts`, `unavailable`, and the `Level` and `Event` fields of the design. Slots without a builder stay empty, are listed in `unavailable` with the reason, and render `[unavailable: …]`. Version-2 snapshot JSON no longer loads, as for 1 → 2; no agent store is deployed. | A missing input is visible in the prompt and in the data, never an empty list that looks like a fact. | Render empty lists; keep schema 2. |
| P10 | **The epoch id never depends on a path.** Problem reasons that enter it say "not found" or "unreadable (…)", and the path is kept apart for display. The input code is hashed by relative path. | The same prompts and config give the same epoch on the laptop and on EC2. | Reasons with paths (found and fixed during the build). |
| P11 | **The epoch includes** the prompts' SHA-256 and versions (or problems), the config SHA-256, call settings per agent and round, the output schema, the snapshot schema version, the input-building code's hash, the Meta rule, and the journal epoch when known. The σ model and the Meta rule version stay null until the code that uses them exists. `epoch_schema = 1` is in it, so a later change of the definition is itself a new epoch. | No input can change unnoticed. | Hash the prompts and config only. |
| P12 | **The decisions are stamped where they are made** (the aggregator and the debate node), not in the risk node. The risk stub stays a pass-through, as its test requires. The run row stores the epoch id and the inputs JSON, so `python -m agents.epoch --db` can show what changed. | Every decision carries the stamps; no node changes behaviour. | Stamp in the risk node. |
| P13 | **Version warnings (AA10)** are logged at graph build time against the store's last run and shown by `python -m agents.epoch --db`. They aren't a separate column: both versions and hashes are stored per run, so a warning can always be derived. | No extra schema for a derived fact. | A warnings column. |
| P14 | **Store migrations are numbered per job:** 3 = the epoch stamps (this job), 4 = the LLM tables, 5 = the discussion. The design doc said "migration 3" for all of them; it is updated. | One migration per PR, so each can be reviewed and rolled back on its own. | One big migration in job 4. |
| P15 | **Four mypy findings** in `agents/graph.py` and `agents/store/sqlite.py` are the same as on the base branch and are left as they are. New modules pass mypy with `--disallow-untyped-defs`. | No unrelated edits in this PR. | Fix them here. |
