# research/gex-feasibility

The study `research/gex_feasibility/`: is listed gold options positioning
big enough for a GEX level effect to be plausible? The rules are in its
[PREREG.md](../../research/gex_feasibility/PREREG.md), committed first, before
any code or data (`94c0b1a`). Decisions taken without the owner, each with
its alternative.

| # | Decision | Conservative because | Alternative |
|---|---|---|---|
| GF1 | **The seal.** `research/SEALING.md` reserves data from 2026-10-01 on for the final strategy test. This study reads a live snapshot (after that date) by the owner's explicit request. It reads magnitudes only: open interest, IV, gamma, whether quotes exist, the underlying futures mid, GC daily volume, and GC closes used only as a dollar multiplier. It reads no XAUUSD bars, no returns, and no price behaviour near strikes. The PREREG states this, and so does the report. | The request is honoured, and the sealed period stays unused for any price question. | Refuse until the seal ends, or ask the owner to amend SEALING.md first. |
| GF2 | **Client id 61.** Taken or reserved: 1 (`TWSConnector`'s default, `deploy/.env.example`), 2 (`tools/data/fetch_data_xauusd.py`), 11 and 21 (scanner), 31 (feed), 97 (the 2026-09-28 probe), 98 (ad-hoc probes, local notes), 996 (watchdog), 999 (entrypoint), and 43 and 44 (named by the owner; nothing in the repo uses them). 61 appears nowhere. `--client-id` overrides it. | No collision with anything known. | Reuse 97, the earlier probe's id. |
| GF3 | **"Next 2–3 expiries" → the next 3,** each at least 2 calendar days away (a nearer expiry's gamma is near-singular and would inflate R). R with 2 expiries is a reported sensitivity. | The bigger set can only raise R, and the verdict sets an upper bound. | 2 expiries as the primary. |
| GF4 | **Unsigned |GEX| with `r = 0`.** Unsigned is an upper bound on any net (signed) exposure. `r = 0` gives the largest Black-76 gamma (`e^(−rT) ≤ 1`, under 1 % at these maturities). | "R < 1 %" then holds for every dealer-sign assumption. | Signed GEX under a dealer-positioning convention (calibrated on SPX, not gold). |
| GF5 | **IV is IBKR's model IV** (`modelGreeks.impliedVol`). A contract with open interest but no IV takes the nearest strike's IV in the same expiry (G4 caps this at 25 % of open interest). **Gate G5** recomputes gamma with IBKR's own IV and `undPrice`, and requires a median relative difference of at most 5 % from IBKR's gamma, so a formula or time-to-expiry error stops the verdict. A contract with IBKR gamma ≤ 0 isn't in G5 (no ratio). | Our gamma is checked against an independent implementation, on the same data. | Back out IV from settlement prices (CME's settlement IVs aren't in this feed). |
| GF6 | **D** is the 20-day average of `Σ volume × 100 × close` over the **nearest 8 GC months** (`TRADES`, 1-day bars, `useRTH=False`), on complete trade dates only. R with the most active month only as D is a reported sensitivity. | All futures volume that matters, in the denominator. | Front month only (a larger R). |
| GF7 | **The open-interest date is inferred.** IBKR sends open interest without a date, so it is taken as the trade date before the snapshot's. The report prints GC futures open interest, to be checked against CME's published figure for that date. | Says what is known, and how to check it. | Claim a date the feed doesn't give. |
| GF8 | **Market hours and holidays** (the probe refuses, exit 3): weekends; the daily 17:00–18:00 New York break; and CME holidays by trade date, both full closures and the abbreviated, no-settlement sessions (2026–2027 hard-coded). Outside those years it refuses, with a message to update `HOLIDAYS`. `analyze.py` gate G1 reuses the same function, loaded from the probe file. | One rule; no snapshot on a thin or unsettled day. | Allow abbreviated sessions. |
| GF9 | **Frozen fallback only for contracts that sent no tick at all** under live data (the owner's rule). A contract with some live values and some missing stays "live", and its missing fields are visible in the JSON and in the gates. Each value is stored with the UTC time it was first received and last changed (polled every 0.25 s), and IBKR's reported data type per contract. | As specified; nothing mixes live and frozen values in one contract. | Re-request frozen for any missing field. |
| GF10 | **The probe writes JSON to stdout only:** nothing is written inside the container or to its volumes, and the host redirect names the file. **The raw JSON isn't committed** (`research/gex_feasibility/.gitignore`): it is IBKR/CME market data, and the repo is public. REPORT.md holds aggregates and the file's SHA-256. | No writes in production volumes; no redistribution of exchange data. | Commit the JSON for reproducibility. |
| GF11 | **One self-contained probe file** (stdlib + ib_insync, Python 3.12), so it runs from stdin in the existing scanner image (c62810d's or `main`'s), with nothing copied into the image. ib_insync is imported only when the probe really runs. Checked: it parses and runs under Python 3.12. | No image rebuild and no deploy needed for a one-off. | Ship it in the image (a deploy for a one-off). |
| GF12 | **Batches of 50 lines** (`--batch`, 1–90; IBKR's default limit is 100, and the scanner holds a few). 15 s per batch for live data and 15 s for frozen data, each ending early once every contract is complete. Error 101 (line limit) → exit 5 with advice. Error 10197 → exit 4 and no JSON. Every subscription is cancelled in a `finally`, then the probe disconnects. | Stays under the limit with room for the running scanner; a partial file is never written. | Larger batches (faster). |
| GF13 | **Only the OG trading class** (monthly options on GC) is in R. The other GC option classes IBKR lists (weeklies and so on) are reported with expiry counts. GLD and OTC options can't be seen. | As pre-registered; the omission is visible. | Include the weeklies. |
| GF14 | **Tests:** `fake_ib.py` scripts IBKR per contract: live, frozen only, silent, or errors 10197 and 101. The probe's tests check the hours and holidays, expiry choice, `underConId` mapping, live-then-frozen, timestamps, the line limit, cancel-all, the exit codes and the output. `analyze.py`'s tests check R against a hand computation, each threshold, each gate, the IV fill rule and the report. `gex.py` is checked against Haug's textbook values and finite differences. Its check against IBKR's gamma runs on a real probe file and skips until one exists (GEX_PROBE_JSON or `data/`). | Everything that can be tested without the gateway is tested; what can't is a gate on the real data. | none |
| GF15 | **Study layout:** the probe is `tools/options_probe.py`, as asked. Its tests sit in the study folder, which `pytest` already collects (`research`), and load it by path (`tools/` isn't a package). The study's `DECISIONS.md` points here (the rule since the restructure is one decision file per branch). | No change to pytest's configuration. | A new `tests/tools/` testpath. |
