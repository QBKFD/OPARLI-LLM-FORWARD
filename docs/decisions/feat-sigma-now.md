# feat/sigma-now

`tools/sigma_now.py`: XAUUSD sigma right now, from the IBKR gateway,
read-only. The owner asked for it on 2026-10-22. These are the decisions I
took without the owner, each with its alternative.

| # | Decision | Conservative because | Alternative |
|---|---|---|---|
| SN1 | **The L tercile cut-offs are now fixed**, by the rule the design already names ("fixed from the σ model's training window", docs/AGENTS_TECHNICAL_DESIGN.md), computed as `research/regime_v2` BASE-L3 does: `nanquantile(L, [1/3, 2/3])` over `vol_block.transform(model.params)` hourly labels in the model's training window (2021-01-03 23:00 .. 2023-12-29 21:59 UTC), then `digitize`. The result is q1 = −0.4144, q2 = −0.0184 over 17,711 labels (the HAR fit had 17,659 rows). They ship as `features/models/l_terciles_parquet2021_2023_v1.json`, with the SHA-256 pinned in `features/l_tercile.py` and checked to belong to the model's SHA-256. A test recomputes them from the parquet when it's present. docs/DECISIONS.md M6 ("cut-offs not defined", so agents don't use `L_tercile`) is left as it is: whether the agents' snapshot uses these is the owner's call. | It is the documented rule and the study's computation, reproducible and pinned; nothing is chosen by eye. | Terciles of recent live L (they drift with the regime); leave the tercile out. |
| SN2 | **The price is the close of the last finished 1-min bar** (`state_at`'s `close_ref`, which sigma_px uses), printed with its bar time. No live quote is requested. The bands are price ± k·sigma_px. | One number, consistent with sigma; no market-data subscription (and no 10197 risk from it). | A live bid/ask mid. |
| SN3 | **Bars: 1-min MIDPOINT, `useRTH=False`, `formatDate=2` (UTC), "6 D"**, the datafeed's IBKR request. The HAR model was fitted on the clean parquet, whose whatToShow isn't recorded (PR #41: probably not plain MIDPOINT). The live datafeed has the same gap. | The repo's live source as it is. | Wait for the backfill to settle whatToShow. |
| SN4 | **`--days` (default 6, as asked).** T needs 120 hourly rows plus one. Right after the Sunday open, 6 trading days can fall short (seen on the fake). The tool then says `insufficient_history` and suggests `--days 7`; it doesn't change the request silently. | The owner's number, with the gap explained. | Fetch 7 D always. |
| SN5 | **Event warning: Forex Factory impact "High", currency USD by default** (`--currencies`), in [now, now + 4 h). The file "covers today" only if now .. now + 4 h lies within its first .. last event date. `events_utc.parquet` ends in 2025, and it isn't on the EC2 host, so today it prints "calendar unavailable". | Gold's main movers are USD releases; no claim of "no event" without coverage. | All currencies. |
| SN6 | **Client id 64** (61 probe, 62 options snapshot, 63 backfill, 11/21 scanner, 31 feed, 996/999). | No collision. | none |
| SN7 | **On EC2 it runs in the scanner image already there**, from a separate read-only checkout mounted at /src. The c62810d image has Python 3.12, pandas, numpy, pyarrow, tzdata and ib_insync, and the tool imports nothing else. Nothing is deployed and the scanner isn't touched. | No deploy; the scanner hold is kept. | Ship it in a new image. |
| SN8 | **The model and cut-off SHA-256 checks run before connecting**, so a tampered file never reaches the gateway. Exit codes: 1 no state, 3 connection or IBKR failure, 4 error 10197. | Fail before any I/O. | none |
